AgePony 5.1.1 fixes the issues found in an internal security review of 5.1.0, and adds a Paste button to Decrypt text.

Security
- Setting your first app password now asks for Face ID or your passcode first.
- ssh-ed25519 keys that can't be encrypted to safely are refused.
- Decrypted copies are removed when AgePony starts and when it locks, so a force-quit no longer leaves one behind.
- In Face ID only mode, if a face is added in Settings, AgePony asks for your app password before using your keys.
- With No lock and an app password, decrypting, signing and showing a key now ask for the app password instead of the device passcode.
- A hardware key that stops working no longer hides a YubiKey the file is also encrypted to.
- A file can't make AgePony retry a hardware key over and over, and a PIN is never sent twice after the key loses contact.

Fixed
- Decrypt text now checks signatures and shows who signed.
- A signature that fails to verify is shown in red, with "Decrypted, signature failed" on files.
- Very large passphrase settings in a file get a clear message instead of a crash.
- Encrypt text scrolls to the result, and the buttons at the bottom of both text screens line up.

Everything still runs on your device. No tracking, no ads.
