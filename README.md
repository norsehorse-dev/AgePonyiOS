# AgePony

AgePony is an iOS app for file encryption and signing, built on
[age](https://age-encryption.org) and SSH. Everything happens on device — no
accounts, no servers, no tracking.

- **Encrypt / decrypt** files and text to age recipients (X25519, ssh-ed25519,
  ssh-rsa) or with a passphrase (scrypt). Output is standard age, readable by the
  `age` CLI on macOS and Linux.
- **Detached signing** via SSHSIG (`ssh-keygen -Y sign/verify` compatible),
  namespace `agepony`. Sign with an in-app SSH key, a Secure Enclave key, or an
  external **FIDO security key** over NFC — including PIN-protected keys
  (`sk-ssh-ed25519` and `sk-ecdsa-sha2-nistp256`).
- **Multi-file bundles**: pick several files and AgePony tars them into one
  `bundle.tar.age`.
- On-device vault with biometric lock; no telemetry (see `PrivacyInfo.xcprivacy`).

## AgePonyCore

The cryptography lives in `Sources/AgePonyCore`, a dependency-free Swift package
(CryptoKit + Security + CommonCrypto). It has no UIKit or app dependencies and can
be reused on its own. It implements age, SSH key parsing, SSHSIG, the FIDO/CTAP2
and PIN-protocol stack, and a USTAR archiver, each pinned to reference vectors in
`Tests/AgePonyCoreTests`.

### Post-quantum recipients

AgePonyCore implements the standardized post-quantum age recipient,
MLKEM768-X25519 — `age1pq1…` public keys and `mlkem768x25519` stanzas —
interoperable with the `age` CLI v1.3.0 and later.

Neither half of the construction is available from Apple's frameworks at this
deployment target, so both are implemented from scratch:

| File | What it is |
| --- | --- |
| `Crypto/SHA3.swift` | Keccak-f[1600] sponge: SHA3-256/512 and the SHAKE XOFs. CryptoKit has no SHA-3. Squeezing is incremental, because ML-KEM's `SampleNTT` rejection-samples for an unbounded number of rounds. |
| `Crypto/MLKEM768.swift` | ML-KEM-768 (FIPS 203, final): NTT, K-PKE, implicit rejection. |
| `Crypto/HpkeMlkem768X25519.swift` | The X-Wing hybrid KEM plus RFC 9180 single-shot HPKE base mode. |
| `Stanzas/HybridStanza.swift` | `HybridRecipient` / `HybridIdentity`. |

The hybrid is "if either half holds, the file holds": breaking it requires both a
quantum computer for ML-KEM and a break of X25519. That is also why a post-quantum
recipient carries age's `postquantum` label — a file readable by an X25519 key is
only as quantum-safe as X25519, so AgePony refuses to mix the two rather than
silently downgrade the guarantee.

FIPS 203 *final* matters: it domain-separates key generation as `G(d ‖ k)`, which
the earlier IPD draft did not. The two derive different keys from the same seed.
The known-answer tests are pinned to vectors generated by `filippo.io/hpke`, the
implementation `age` itself uses, so a drift toward the draft fails loudly.

**The app UI does not offer post-quantum identities yet.** The library does, and
files produced with it interoperate with standard `age`.

### Bounded memory

Every format AgePony handles has a streaming path that holds a fixed working
buffer regardless of file size, so a 1 GB file behaves like a 1 KB one:

- `Age.encryptStream` / `decryptStream`, and the chunked payload underneath
- `AgeArmorStream.swift` — an armor encoding sink and a decoding source that
  substitutes for an `InputStream`
- `Archive/TarArchiveStream.swift` — tar in both directions: push (`writeEntry`)
  and pull (`source`), because encrypt reads its plaintext from a stream while
  decrypt writes to one
- `Signing/SSHSigHashStream.swift` — incremental message hashing, so a large file
  can be signed without being held
- `Age.parseHeaderStream` / `canDecryptStream` — a header-only probe that reports
  what a file is encrypted to, and whether you hold a key for it, without
  decrypting; instant at any file size

Each streaming path is tested for byte-identical output against its whole-buffer
counterpart, so the two cannot drift.

### Signed bundles

`Archive/SignedBundle.swift` is a small USTAR container carrying a payload
alongside a detached SSHSIG over it. The bundle is then age-encrypted as a unit —
sign-then-encrypt — so an encrypt-and-sign produces a single file and the signer's
identity stays inside the ciphertext instead of being exposed in a signature
sitting next to it. The format matches the Android implementation byte for byte.

`SignedBundleUnwrappingSink` strips the container mid-stream while hashing the
payload in passing, and passes anything that is not a bundle straight through, so
the decrypt path can route every output through one code path.

## Build

Open `AgePony.xcodeproj` in Xcode and build the `AgePony` scheme (iOS 18.6+). Set
your own team under Signing & Capabilities — `DEVELOPMENT_TEAM` in the committed
project is NorseHorse's and will not match yours. The NFC security-key feature
needs the Near Field Communication Tag Reading capability and a real device; NFC
is not available in the simulator.

Run the crypto tests:

    swift test
